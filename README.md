# VG+ | صندوق التواصل المباشر

الموقع يتكون من واجهة عامة على GitHub Pages، وخادم Cloudflare Workers / Sites وقاعدة D1 دائمة. لوحة الفريق تعمل على الخادم وتستخدم رموزاً مستقلة للأعضاء، دون حساب ChatGPT أو تسجيل عضوية عام.

## الروابط

- الواجهة: https://7madybar.github.io/---------------------/
- الخادم والواجهة البديلة: https://vg-visionary-feedback.clayimage8.chatgpt.site/
- لوحة الفريق: https://7madybar.github.io/---------------------/team/
- اللوحة المستقلة عند الحاجة: https://vg-visionary-feedback.clayimage8.chatgpt.site/admin

GitHub Pages يستضيف ملفات ثابتة فقط. لذلك لا يكفي رفع ملفات React/TypeScript إليه. ملف index.html ومجلد pages-assets يحتويان النسخة المبنية للمتصفح، وترسل البيانات إلى الخادم الحقيقي.

## تعديل الواجهة ونشرها على GitHub

1. ثبّت Node.js 22.13 أو أحدث، ثم `npm ci`.
2. عدّل ملفات app/components/CSS في المصدر.
3. نفّذ `npm run build:pages`.
4. أضف index.html وpages-assets و.nojekyll إلى commit مع تعديلات المصدر، ثم ادفع إلى فرع main. إعداد Pages الحالي ينشر من جذر هذا الفرع.
5. إعداد مسار المستودع وعنوان الخادم موجود في vite.pages.config.ts. الأصول تستخدم مسار المستودع الصحيح.

لا يعدّل بناء Pages الخادم تلقائياً. إذا غيّرت API أو الصلاحيات أو مخطط DB، ابنِ الخادم وانشره على Sites أيضاً. ملف scripts/build-github-pages.mjs يجعل الواجهة الثابتة مبنية من نفس مكونات المصدر، دون نسخة تصميم منفصلة.

## الخادم وقاعدة البيانات

.openai/hosting.json يعلن الربط DB. تهيئ Sites قاعدة D1 وتطبق ترحيلات drizzle عند النشر. الجداول تحفظ الرسائل والتعليقات والأعضاء وتجزئات الرموز والجلسات. بيانات التطوير منفصلة عن الإنتاج.

متغيرات بيئة الخادم:

| المتغير | الاستخدام |
| --- | --- |
| RATE_LIMIT_SALT | سر عشوائي لتجزئة معرف الشبكة وحدود المحاولات. |
| PUBLIC_FORM_ORIGIN | https://7madybar.github.io؛ يتيح CORS فقط لـ POST /api/challenge وPOST /api/submit. |
| TEAM_CODE_PEPPER | سر عشوائي لا يقل عن 32 حرفاً لحساب HMAC لرموز الفريق. احتفظ به ثابتاً؛ تغييره يبطل كل الرموز الحالية. |
| INITIAL_ADMIN_EMAIL | معرّف أول مدير محفوظ على الخادم؛ لا يحتاج إلى تسجيل حساب خارجي. |
| INITIAL_ADMIN_CODE_HASH | HMAC-SHA256 لرمز المدير الأول، ويستهلك للتهيئة مرة واحدة فقط. لا تضع الرمز نفسه في الشيفرة. |

احفظ قيم الإنتاج في إعدادات أسرار Sites. .env.example يوضح الأسماء فقط. لا ترفع .dev.vars أو الأسرار أو قواعد البيانات المحلية إلى GitHub.

لتوليد رمز المدير الأول وتجزئته محلياً في الطرفية، دون حفظه في المصدر، استخدم متغيراً سرياً TEAM_CODE_PEPPER ثم احسب HMAC على النص team-code: متبوعاً بالرمز بعد إزالة المسافات والشرطات والبادئة VG. مثال التطوير في الفحوص يستخدم VG-TESTA-TESTB-TESTC-TESTD فقط، ولا يُستخدم في الإنتاج.

## دخول الفريق وإدارته

1. افتح /admin وأدخل رمز المدير الذي استلمته بشكل خاص. لا يلزم تسجيل دخول إلى ChatGPT.
2. من إدارة الفريق أضف الاسم وحدد صلاحية عضو أو مدير. يصدر الخادم رمزاً عشوائياً مستقلاً يظهر مرة واحدة؛ انسخه وسلّمه لصاحبه.
3. الرمز غير محفوظ كنص صريح. إذا فُقد، أصدر رمزاً جديداً؛ يُلغى السابق وجلسات العضو الأخرى فوراً. تبقى جلسة المدير الحالية عند تجديد رمزه الخاص حتى يستطيع نسخ البديل.
4. يمكن إيقاف عضو أو تغيير دوره. الإيقاف يسحب جلساته، وتتحقق كل قراءة/كتابة من العضوية الحالية على الخادم.
5. مدة الجلسة الافتراضية 8 ساعات ويغيّرها المالك من إعدادات الدخول، وتحفظ في Cookie من نوع Secure وHttpOnly وSameSite=Lax. تسجيل الخروج يلغيها على الخادم.
6. بعد أول تهيئة يمكن إزالة INITIAL_ADMIN_CODE_HASH من البيئة وإعادة النشر. الرمز الحالي محفوظ كتجزئة في DB، ولا تعيد التهيئة إحياء حساب موقوف.

## التطوير المحلي والفحوص

انسخ .env.example إلى .dev.vars واضبط قيماً محلية منفصلة. ابنِ الخادم باستخدام npm run build ثم طبق ملفات SQL في drizzle بالترتيب، مرة واحدة فقط لكل قاعدة:

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_harsh_drax.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_flippant_calypso.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_dry_doctor_strange.sql
npm run dev
```

الفحوص: npx tsc --noEmit، ثم node tests/integration.mjs http://127.0.0.1:5173. فحوص التكامل مخصصة لقاعدة تطوير فقط، بمعرف المدير seedy@sites.test ورمز الاختبار المذكور أعلاه.

## الأمان والخصوصية

كل قراءة للرسائل أو التعليقات، وكل تغيير في الحالات والأعضاء، يتطلب جلسة صحيحة وعضوية مفعّلة؛ إدارة الرموز تتطلب مديراً. CORS لا يتيح قراءة أي بيانات خاصة، ولا يتيح تسجيل الدخول من GitHub. الدخول واللوحة يفتحان على نطاق الخادم فقط.

الحماية من الإزعاج: حد للرسائل والمحاولات وتذاكر التحقق، حقل فخ، تذكرة عشوائية مرتبطة بتجزئة الشبكة، حد أدنى زمني، تحقق من Origin، حدود أحجام الطلبات والحقول، ومعرف فريد لمنع تكرار الإرسال. حد الدخول 10 محاولات لكل شبكة في 10 دقائق.

لا يستخدم التطبيق localStorage كقاعدة رسائل أو لحفظ رموز الدخول. الاسم اختياري ولا يعني إخفاء الهوية الكامل. لا يوجد تشفير طرف إلى طرف. حافظ على سرية رموز الفريق؛ أي شخص يحصل على رمز يستطيع استخدام صلاحية صاحبه حتى إيقافه أو تدويره.

## المالك والمدير والعضو

المالك هو الحساب الأصلي الذي عُرّف عند تهيئة الموقع؛ يُحدّث دوره مرة واحدة دون تغيير رمزه أو إعادة تفعيل حساب موقوف. لا توجد واجهة عامة لإنشاء مالك آخر أو تغيير صلاحية المالك.

- المالك يدير المديرين والأعضاء، ويستطيع تجديد رمزه الخاص. لا يمكن إيقافه أو تغيير صلاحية المالك من لوحة الإدارة.
- المدير يستطيع إضافة مدير أو عضو، وتغيير صلاحياتهم أو إيقافهم وتجديد رموزهم. يحظر الخادم أي تغيير لحساب المالك أو رمزه، بصرف النظر عن الأزرار الظاهرة في الواجهة.
- العضو يستطيع قراءة الرسائل ومناقشتها وتحديث حالاتها، ويشاهد قائمة الفريق وأسماءهم وصلاحياتهم وحالاتهم. لا يستطيع إضافة أشخاص أو تعديلهم أو إصدار رموز.
- قائمة الفريق لا تعيد بريد الأعضاء أو تجزئات الرموز أو أسرار الجلسات؛ تستخدم معرفات عامة للإجراءات المسموحة.
- المالك وحده يستطيع حذف حساب مدير أو عضو نهائياً بعد التأكيد. يُلغى رمز الحساب وجميع جلساته في عملية قاعدة بيانات واحدة، وتبقى تعليقاته السابقة محفوظة باسمه. لا يستطيع المدير أو العضو تنفيذ الحذف حتى بطلب API مباشر، ولا يمكن حذف المالك. لإيقاف مؤقت قابل للتراجع استخدم «إيقاف الوصول».

## عنوان لوحة الفريق على GitHub

### التحكم في مدة الجلسة

من «إعدادات الدخول» يستطيع المالك وحده تحديد مدة جميع الجلسات الجديدة من 1 إلى 8760 ساعة، أو اختيار «بدون انتهاء تلقائي». تبقى القيمة الافتراضية 8 ساعات. تُحفظ السياسة في جدول settings تحت المفتاح team_session_hours، ولا يلزم تغيير متغيرات البيئة أو إنشاء رموز جديدة. المدير والعضو ممنوعان من قراءة هذا الإعداد أو تغييره عبر API.

تغيير إعداد مدة الجلسة يسري عند تسجيل الدخول التالي فقط؛ الجلسات المفتوحة تحتفظ بمدتها السابقة، مع التحقق دائماً من صلاحية رمز العضو. تكون نهاية الجلسة عند أقرب موعد بين نهاية مدتها ونهاية صلاحية الرمز. عند اختيار جلسة بلا انتهاء ورمز دائم تستخدم expires_at=0، مع بقاء تسجيل الخروج وإيقاف العضو وتجديد الرمز فعّالة (تجديد رمزك الخاص يبقي جلستك الحالية ضمن صلاحية الرمز الجديد). يُطلب من المتصفح حفظ Cookie حتى 400 يوم، وقد يفرض مدة أقصر أو يحذفها؛ لذلك لا نضمن بقاء الدخول إلى الأبد على الجهاز.

### صلاحية رموز الدخول

المالك والمدير يستطيعان تحديد رمز دائم أو صلاحية من 1 إلى 8760 ساعة عند إضافة عضو أو إصدار رمز بديل. من زر «صلاحية الرمز» يمكن تغيير صلاحية الرمز الحالي دون تغييره؛ تُحسب المدة من وقت الحفظ، وتُعرض نهاية الصلاحية في قائمة الفريق. المدير لا يستطيع تعديل رمز المالك أو صلاحيته، والعضو لا يستطيع تعديل أي رمز. حذف الحساب يبقى للمالك فقط، وإعداد مدة الجلسة العامة يبقى للمالك فقط.

الترحيل 0002 يضيف عمود access_code_expires_at قابلاً لـ NULL؛ كل الرموز الموجودة تبقى دائمة دون تغيير رموزها أو تجزئاتها. عند انتهاء رمز مؤقت يرفض الخادم الدخول وجميع طلبات الجلسات المرتبطة به، بما فيها الجلسات التي كانت بلا انتهاء تلقائي. جعل الرمز دائماً لا يمدد تلقائياً جلسة لها موعد انتهاء سابق؛ يلزم دخول جديد. لا تغيّر ترحيلات قاعدة البيانات المطبقة، وطبّق الترحيل الجديد محلياً مرة واحدة؛ تطبقه استضافة Sites قبل نشر النسخة الجديدة.

رابط الفريق الظاهر هو https://7madybar.github.io/---------------------/team/ . تعرض هذه الصفحة لوحة الخادم داخل إطار مخصص. يظل الخادم وقاعدة البيانات على استضافتهما الحالية؛ هذا عرض للوحة داخل نطاق GitHub وليس نقلاً لخادم التطبيق إلى GitHub Pages.

تستخدم جلسة الإطار Cookie مستقلة Secure وHttpOnly وSameSite=None وPartitioned، بمدة الجلسة التي يحددها المالك. تبقى الجلسة المباشرة على نطاق الخادم SameSite=Lax. لا تُحفظ الرموز أو الجلسات في localStorage، ولا يُفتح CORS لقراءة الرسائل أو لإدارة الفريق أو تسجيل الدخول. يحدد CSP الآباء المسموح لهم بتضمين اللوحة بنطاق GitHub الخاص بالموقع ونفس نطاق الخادم فقط.

يتطلب دخول الإطار متصفحاً محدثاً يدعم حفظ الجلسة المعزولة. تتحقق واجهة الدخول من حفظ الجلسة قبل عرض نجاح الدخول؛ عند المنع تظهر رسالة واضحة مع خيار فتح اللوحة المستقلة. التنقل إلى صندوق التواصل يعود إلى صفحة GitHub الرئيسية.

الأمر npm run build:pages يبني الآن index.html وteam/index.html وpages-assets. يجب رفع هذه الملفات مع المصدر عند نشر تغيير للرابط.

## إدارة الرسائل

من داخل «تفاصيل الرسالة» يستطيع المالك فقط اختيار «حذف الرسالة»، ثم تأكيد حذفها نهائياً مع جميع التعليقات الداخلية المرتبطة بها. لا يظهر هذا الخيار للمدير أو العضو، والخادم يرفض طلب الحذف منهما حتى إذا أُرسل مباشرة. تُحذف الرسالة وتعليقاتها وتذكرة إرسالها في عملية واحدة؛ لا يحذف هذا الإجراء حساب المرسل أو عضويات الفريق أو الرسائل الأخرى. لا يمكن التراجع عن الحذف.

تعرض اللوحة ملخصاً لحالات الصندوق مع تصفية سريعة، وزر مسح الفلاتر، وآخر وقت تحديث. تُحدّث القائمة كل دقيقة أثناء ظهور الصفحة، وعند العودة إليها. تعذّر التحديث يحافظ على آخر نتائج مع رسالة واضحة؛ لا تظهر رسالة حذف ناجح إلا بعد تأكيد الخادم. يُضبط رقم الصفحة تلقائياً إذا قل عدد النتائج بعد حذف آخر رسالة منها. أضيف عداد حروف للتعليقات وتحسين لتخطيط الهاتف وتأكيد الحذف بلوحة المفاتيح.

## استعادة المالك من إدارة الاستضافة

الرموز مخزنة كتجزئات ولا يمكن عرض الرمز الحالي بعد إخفائه. إذا تعذر الدخول، يستطيع صاحب الاستضافة الموثّق تجهيز استعادة لمرة واحدة. شغّل `node scripts/generate-owner-recovery.mjs` في بيئة خاصة؛ المخرجات تحتوي رمزاً جديداً ومعرّفاً وبرهان SHA-256 وموعد انتهاء نافذة الاستعادة. لا تحفظ هذه المخرجات في ملفات المصدر أو Git.

من إدارة أسرار الاستضافة، اضبط فقط `OWNER_RECOVERY_ID` و`OWNER_RECOVERY_PROOF` و`OWNER_RECOVERY_EXPIRES_AT` بالقيم المولّدة، ثم انشر نسخة الخادم. لا تغير TEAM_CODE_PEPPER أو INITIAL_ADMIN_CODE_HASH أو أي رمز آخر. أدخل الرمز الجديد عبر دخول الفريق قبل انتهاء نافذة الاستعادة (30 دقيقة؛ الخادم يرفض نافذة تتجاوز ساعة). تُستعاد عضوية المالك الأصلية المحددة في INITIAL_ADMIN_EMAIL فقط إذا كانت موجودة بدور owner؛ لا تُنشأ عضوية جديدة ولا يُرقّى مدير أو عضو.

أول استخدام صحيح يحدث تجزئة رمز المالك ويجعله دائماً ويفعّل الحساب ويلغي جلساته السابقة في عملية واحدة، ويسجل استهلاك معرف الاستعادة في settings. أي محاولة لاحقة بالمعرف نفسه لا تعيد ضبط رمز أو صلاحية أو تفعيل الحساب بعد تغييرها. تظل حدود محاولات الدخول مطبقة. احذف مفاتيح الاستعادة الثلاثة من إعداد الاستضافة بعد نجاح التحقق، ثم أعد نشر النسخة نفسها. لا تحذف سجل الاستهلاك من الإنتاج. إعداد الاستعادة معطل في التشغيل العادي ما لم تُضبط القيم الثلاث؛ لا توجد صفحة عامة لاستعادة المالك.



## متابعة الزائر وسجل الحالات

بعد إرسال رسالة جديدة يظهر رمز متابعة خاص كامل. احتفظ به خارج الموقع أو انسخه؛ لا تُحفظ الرسائل أو الرموز في localStorage. يفتح الزائر «متابعة رسالة» ويدخل الرمز من أي جهاز لعرض الحالة وسجل التغييرات مع اسم عضو الفريق الذي حدّد كل حالة وتوقيتها. لا تعني حالة «قيد المراجعة» أن كل أعضاء الفريق قرؤوا الرسالة.

يستخدم الرمز توقيع HMAC-SHA-256 مفصول المجال بواسطة RATE_LIMIT_SALT الموجود، ويصدر بعد تأكيد حفظ الرسالة ويظل ثابتاً عند إعادة الطلب نفسه. لا يلزم إضافة أسرار بيئة جديدة أو تبديل رموز الفريق. لا تضع الرمز في الرابط أو سجلات الطلبات. تغيير RATE_LIMIT_SALT سيبطل رموز المتابعة السابقة؛ حافظ عليه أثناء النشر المعتاد. تعيد POST /api/track الحالة وتاريخ الإرسال وسجل الحالات فقط، مع حد 30 محاولة لكل عشر دقائق، وتظل الرسائل والأسماء والتعليقات الداخلية وعمليات الفريق محمية بالمصادقة.

امتداد CORS الوحيد هو POST /api/track إلى جانب challenge وsubmit لنطاق GitHub المهيأ فقط، دون إرسال cookies أو فتح أي مسار خاص. معرفة رقم الرسالة المختصر أو UUID وحده لا تسمح بالمتابعة. يحتفظ من يملك الرمز بإمكانية رؤية أسماء من غيّروا الحالة؛ الواجهة توضّح خصوصية الرمز.

الترحيل الإضافي ينشئ جدول status_history فقط، ولا يغيّر الرسائل أو الأعضاء أو الإعدادات الموجودة. يُسجّل الاسم وقت التغيير ولا يتغير بحذف العضو لاحقاً. لا يُنشأ حدث جديد إذا اختيرت الحالة نفسها. الحالات القديمة التي لا تملك سجلاً لا تُنسب إلى شخص أو وقت غير معروف، والرموز المختصرة القديمة غير قابلة للتحويل إلى رمز متابعة. حذف المالك للرسالة يحذف سجلها وتعليقاتها وتذكرة إرسالها ذرياً، ويصبح رمز متابعتها غير صالح.
