# VG+ | Visionary Growth

تطبيق عربي كامل لصندوق التواصل، يعمل على Sites باستخدام Vinext / React وCloudflare Workers وD1. جميع الرسائل والتعليقات والأعضاء محفوظون في قاعدة البيانات المشتركة. لا يستخدم localStorage لحفظ الرسائل.

## التشغيل المحلي

يتطلب Node.js 22.13 أو أحدث، Git وtar.

1. `npm ci --prefer-offline --no-audit --no-fund`
2. انسخ `.env.example` إلى `.dev.vars` (ملف محلي مستثنى من Git).
3. للتجربة المحلية فقط اضبط `INITIAL_ADMIN_EMAIL=seedy@sites.test`، وضع قيمة عشوائية في `RATE_LIMIT_SALT`.
4. `npm run build` لتوليد `dist/server/wrangler.json` وربط DB.
5. طبّق ملفات SQL الموجودة في `drizzle` بالترتيب، مرة واحدة لكل قاعدة محلية، باستخدام الأمر التالي مع اسم الملف الفعلي:

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_harsh_drax.sql
```

6. `npm run dev` ثم افتح العنوان المحلي المطبوع (عادة http://localhost:5173).
7. افتح `/admin` وسجل الدخول. محاكاة تسجيل الدخول في وضع التطوير المحلي تستخدم `seedy@sites.test`؛ لا تُضمّن هذه المحاكاة في بناء الإنتاج.
8. `node tests/integration.mjs http://localhost:5173` يفحص الإرسال والتكرار والتحقق وحدود المعدل والتعليقات وصلاحيات الأعضاء. يستعمل قاعدة الاختبار المحلية ويمسح بياناته بعد التشغيل.

عند تعديل المخطط لاحقاً شغّل `npm run db:generate` وأضف ترحيلاً جديداً؛ لا تعدّل ترحيلاً سبق تطبيقه.

## قاعدة البيانات والإنتاج على Sites

`.openai/hosting.json` يعلن `d1: "DB"`. تنشئ Sites قاعدة D1 وتربطها وتطبّق ترحيلات `drizzle` أثناء النشر. لا توجد حاجة لمفتاح قاعدة بيانات في المتصفح. البيانات المحلية منفصلة تماماً عن بيانات الموقع المنشور.

اضبط متغيرات بيئة الإنتاج عبر إعدادات أسرار Sites ثم انشر النسخة:

| المتغير | الغرض |
| --- | --- |
| `INITIAL_ADMIN_EMAIL` | البريد الموثق لحساب ChatGPT الذي سيصبح أول مدير. يتطلب تسجيل دخوله بنفسه. |
| `RATE_LIMIT_SALT` | قيمة سرية عشوائية ثابتة لتجزئة معرف الشبكة في الحماية من الإزعاج. ولّد 32 بايت عشوائية. |

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

لا تُحفظ القيم السرية في المصدر أو `.openai/hosting.json`. `.env.example` يوضح الأسماء فقط. في هذه النسخة ضُبط بريد المدير الذي زوّد به صاحب الطلب كسر في بيئة الإنتاج، مع قيمة عشوائية للحماية.

يجب أن تكون إتاحة الموقع على Sites «عام» كي يرسل الزوار دون حساب. إعداد الإتاحة العام لا يمنح صلاحيات لوحة الفريق: فحص العضوية على الخادم مستقل. قد تبدأ النسخة المنشورة خاصة حسب سياسة الاستضافة؛ تحقق من حالة الإتاحة قبل مشاركة الرابط مع الجمهور.

## أول مدير وإدارة الفريق

1. افتح `/admin` وسجل الدخول عبر ChatGPT بالبريد المحدد في `INITIAL_ADMIN_EMAIL`.
2. يتم إنشاء صلاحية المدير مرة واحدة فقط في معاملة ذرية، وربطها بمعرّف حسابه الثابت. لا يُمنح أي حساب آخر صلاحية تلقائية.
3. من «إدارة الفريق» أضف اسم العضو وبريد حساب ChatGPT والصلاحية. لا تُرسل رسائل بريد تلقائياً. أعط العضو رابط الموقع بالطريقة التي تختارها.
4. عند أول دخول صحيح يُربط البريد بمعرّف حساب ذلك العضو. التسجيل لدى مزود الهوية لا يسجل عضوية في الفريق.
5. يمكن للمدير تفعيل أو إيقاف الأعضاء وتغيير دورهم؛ تُطبق التغييرات في الطلب التالي. لا يستطيع المدير إيقاف نفسه أو تغيير دوره من اللوحة.
6. بعد أول دخول ناجح يمكن إزالة `INITIAL_ADMIN_EMAIL` من البيئة وإعادة النشر. يبقى المدير محفوظاً في DB، ولا يعيد المتغير إنشاء حساب أُوقفت عضويته.

لا توجد كلمات مرور مشتركة أو صفحة تسجيل عضوية عامة. تسجيل الدخول واستعادة حساب الهوية يديرهما ChatGPT/Sites.

## حدود الأمان والخصوصية

- كل قراءة للرسائل والتعليقات وكل تغيير أو إدارة أعضاء تتطلب هوية موثقة وعضوية مفعلة على الخادم. إدارة الأعضاء تتطلب دور مدير.
- صفحة `/admin` نفسها تتحقق على الخادم. ردود البيانات الخاصة غير قابلة للتخزين المؤقت.
- الواجهات العامة الوحيدة: `POST /api/challenge` و`POST /api/submit`. تعيد تأكيد الحفظ فقط، ولا تعيد نصوص الرسائل أو التعليقات.
- تحقق على الخادم من الأدوار والأنواع والحدود: رسالة 1–1200 حرف، اسم حتى 80، تعليق 1–2000. استعلامات SQL مربوطة المعاملات، والنصوص تُعرض كنص لا كـHTML.
- الحماية الأساسية من الإزعاج: حقل فخ، تذكرة عشوائية مرتبطة بتجزئة الشبكة وصالحة 30 دقيقة، انتظار ثانيتين، 5 رسائل لكل نافذة 10 دقائق، و30 تذكرة تحقق لكل نافذة. العدادات دائمة وذرية في D1. ليست CAPTCHA، وقد يشترك زوار نفس الشبكة في الحد.
- منع التكرار: معرّف طلب فريد في DB؛ إعادة نفس الطلب تعيد نفس تأكيد الحفظ. لا تُمسح المدخلات إلا بعد تأكيد الخادم.
- تُرفض طلبات التغيير من مصادر أخرى أو بصيغ غير JSON، والطلبات الأكبر من 16KB. تحقّق من `Origin` يحد من CSRF؛ لا يوجد CORS عام للبيانات الخاصة.
- عدم إدخال اسم لا يعني إخفاء الهوية الكامل. لا يُخزن IP الخام في جداول التطبيق، لكن الاستضافة ومزود الهوية قد يعالجان بيانات اتصال. لا يوجد تشفير طرف إلى طرف.
- يُحذف تخزين تحديات التحقق القديمة وعدادات الحماية عند إصدار تذكرة جديدة. الرسائل والتعليقات لا تُحذف تلقائياً؛ إدارة الاحتفاظ والنسخ الاحتياطي عبر أدوات قاعدة البيانات حسب سياسة الفريق.
- الثقة في ترويسات `oai-authenticated-*` و`cf-connecting-ip` تعتمد على بوابة Sites الموثوقة. لا تنشر التطبيق على خادم يقبل هذه الترويسات من المستخدم مباشرة. النقل إلى استضافة أخرى يحتاج تكامل هوية موثوقاً وفحص الترويسات عند البوابة.
